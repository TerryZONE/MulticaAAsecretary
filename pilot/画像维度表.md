# 偶像画像维度表 v1（2026-07-07）

档案与流水正交：流水（posts/snapshots）按时间存，画像（profiles 表）按人存。
画像字段由每日 Claude 任务在读日报数据时**顺手沉淀**（看到证据就更新对应字段），人工可随时修正。

| 维度 | 字段 | 取值/形态 | 填充方式 |
|------|------|----------|---------|
| 风格系别 | style | 王道/暗黑/元气/摇滚/和风/病娇/猫系…（可复合） | 简介+行业报告初始化，日报观察修正 |
| 厂牌归属 | agency | 事务所/厂牌名 + 关系（旗下/联营/自营） | 简介/认证/转发关系，自动性高 |

| 粉丝结构 | fan_structure | 规模档（快照）+ 性别倾向 + 消费力信号（特典售罄/切数纪录） | 快照自动 + 日报证据 |
| 商业化历史 | commercial | JSON 数组：[{date, event, source_post}]（商务/联名/代言/商演） | 日报见到商务帖即追加，**只增不改** |
| 舆情记录 | incidents | JSON 数组：[{date, event, source}]（争议/翻车/解散/退团） | 日报+揭示板投稿，只增不改 |
| 轨迹 | （由 snapshots 计算） | 粉丝增速曲线、互动率趋势 | 全自动，查询时现算 |
| 其他观察 | notes | 自由文本 | 随手记 |

## 底层数据保全原则

1. **posts 表只增不删**：对方删博，我们仍保留全文与 raw_json；`deleted_suspect` 标记疑删日期——疑删记录本身就是舆情信号
2. **raw_json 全量存**：今天想不到的维度，明天可以从原料里重新加工；临时抓取做不到，临时加工做得到
3. **改名史**（name_history）：成员改名频繁，uid 恒定，历史昵称可追溯
4. 长文帖（is_long=1）文本被 API 截断，全文补采列入待办

## 业务判断（如商务匹配）的取数路径

「谁适合卖果汁」类查询 = profiles.style/fan_structure 过滤 → snapshots 轨迹排序 → commercial 查同类先例 → incidents 排雷 → posts 原文佐证。全部离线可答，无需临时抓取。
